# 一键导出全部微信会话设计

## 背景

当前仓库已经具备三段独立能力：

1. `find_all_keys_macos` 从运行中的微信进程提取每个数据库的密钥。
2. `decrypt_db.py` 使用 `all_keys.json` 解密本地微信数据库。
3. `export_chat.py` 按单个联系人或群聊导出聊天记录。

用户希望新增一个“一键导出聊天记录”能力，目标是执行一次命令后自动完成提取密钥、解密数据库、遍历全部会话并批量导出。导出结果不再输出 `txt/csv`，只生成参考样例风格的 `.json` 文件；文件名优先使用联系人名或群名。

## 目标

新增一个独立的命令行入口，默认串起以下完整流程：

1. 检查并编译 `find_all_keys_macos`。
2. 调用扫描器生成最新的 `all_keys.json`。
3. 调用现有解密逻辑生成明文数据库。
4. 遍历全部会话并逐个导出为结构化 JSON。
5. 输出导出摘要，包括总会话数、成功数、失败数和输出目录。

## 非目标

- 不实现图形界面。
- 不导出图片、视频、语音等媒体文件本体。
- 不改变现有单会话导出命令的使用方式。
- 不要求自动化测试依赖真实微信进程或真实本机登录态。

## 方案选择

### 备选方案

1. 新增独立编排脚本。
2. 直接扩展 `export_chat.py`，同时承载单会话导出和整链路一键导出。
3. 使用 shell 脚本串联现有命令。

### 结论

选择方案 1：新增独立编排脚本，例如 `export_all_in_one.py`。

原因如下：

- 最小化对现有 `decrypt_db.py` 和 `export_chat.py` 的侵入，降低回归风险。
- 将“编排流程”和“导出某个会话”分离，职责更清晰。
- JSON 结构构建、错误处理和后续扩展更适合放在 Python 中，而不是 shell。

## 用户接口

新增主命令：

```bash
python3 export_all_in_one.py --output ~/Downloads/wechat-export
```

### 参数

- `--output`：最终 JSON 文件输出目录。
- `--keep-decrypted`：保留中间解密目录，便于排障。
- `--skip-scan`：跳过密钥提取，复用现有 `all_keys.json`。
- `--skip-decrypt`：跳过数据库解密，复用现有解密结果。

默认情况下，命令会自动执行“编译扫描器 -> 提取密钥 -> 解密数据库 -> 全量导出”整条链路。

## 架构设计

新增的编排脚本负责调度，不直接复制底层实现。设计上拆成四个清晰步骤：

1. `ensure_key_scanner()`：检查 `find_all_keys_macos` 是否存在；若不存在，则调用 `cc -O2 -o find_all_keys_macos find_all_keys_macos.c -framework Foundation` 编译。
2. `run_key_scan()`：执行 `sudo ./find_all_keys_macos`，确认 `all_keys.json` 已生成且内容可读。
3. `run_decrypt()`：调用现有解密逻辑完成数据库解密。
4. `export_all_sessions()`：遍历所有会话，逐个构建结构化 JSON 并写入输出目录。

为了减少重复代码，导出相关的数据库查询、联系人信息解析、消息归一化等能力应从现有 `export_chat.py` 中提取为可复用函数，而不是在新脚本中重新实现一套逻辑。

## 数据模型

每个会话生成一个独立 JSON 文件，顶层结构与参考样例对齐：

```json
{
  "chatlab": {
    "version": "0.0.2",
    "exportedAt": 1776240866,
    "generator": "wechat-export-macos"
  },
  "meta": {
    "name": "会话名",
    "platform": "wechat",
    "type": "group",
    "ownerId": "wxid_xxx",
    "groupId": "xxxx@chatroom"
  },
  "members": [
    {
      "platformId": "wxid_xxx",
      "accountName": "昵称"
    }
  ],
  "messages": [
    {
      "sender": "wxid_xxx",
      "accountName": "昵称",
      "timestamp": 1722857963,
      "type": 0,
      "content": "消息内容",
      "platformMessageId": "537145736263414100"
    }
  ]
}
```

### 字段约定

#### `chatlab`

- `version`：导出格式版本，初始固定为 `0.0.2`，与用户给定样例保持一致。
- `exportedAt`：导出时的 Unix 秒级时间戳。
- `generator`：固定为当前项目名 `wechat-export-macos`。

#### `meta`

- `name`：会话展示名，优先级为 `remark > nick_name > alias > username`。
- `platform`：固定为 `wechat`。
- `type`：群聊为 `group`，其他会话为 `direct`。
- `ownerId`：自动识别出的当前用户 wxid；识别失败时允许为空字符串，但仍保留字段。
- `groupId`：群聊使用 chatroom id；单聊使用联系人 username。

#### `members`

- 字段固定为 `platformId` 和 `accountName`。
- 群聊场景下，成员集合至少包含：
  - 当前消息中实际出现过的发送者。
  - 当前会话自身（群 ID + 群名），以兼容参考样例风格。
- 单聊场景下，至少包含当前用户和对方联系人。
- 成员名解析优先使用联系人数据库；找不到时回退到 wxid 原值。

#### `messages`

- `sender`：发送者平台 ID，优先使用真实发送者 wxid。
- `accountName`：发送者展示名。
- `timestamp`：消息 Unix 秒级时间戳。
- `type`：导出格式内部消息类型。当前阶段采用保守映射：
  - 文本消息导出为 `0`。
  - 非文本消息统一导出为 `1`，并在 `content` 中保留可读占位信息。
- `content`：文本直接输出消息正文；媒体、系统消息等先输出简短占位文本。
- `platformMessageId`：优先使用 `server_id`，若为空则回退到 `local_id`，最终统一转成字符串。
- `chatRecords`：仅在消息中存在转发/聊天记录子结构时才输出；本期先不主动构造。

## 会话识别与遍历

导出逻辑需要遍历所有 `message_*.db` 中的 `Msg_<md5(username)>` 表，并将跨分片数据库中的同一会话消息合并后按时间排序。

会话映射策略：

1. 先从 `contact.db` 构建 `username -> 联系人信息` 映射。
2. 使用 `md5(username)` 生成理论表名，反向匹配到实际 `Msg_*` 表。
3. 对于联系人库无法解析的表：
   - 优先检查是否能在 `Name2Id` 或其他会话索引中还原 username。
   - 仍无法解析时，将该表视为匿名会话，文件名回退为表名。

## 文件命名

每个会话写成单独 `.json` 文件，默认命名为会话展示名，例如：

- `张三.json`
- `黑手册目前唯一群🪺🐉.json`

文件名处理规则：

1. 保留普通中文、英文、数字、emoji。
2. 替换文件系统非法字符，例如 `/`、`:`、空字节。
3. 去掉首尾空白和非法结尾字符。
4. 若多个会话清洗后文件名相同，则自动追加 `-2`、`-3` 等后缀。

## 错误处理

### 阻断型错误

以下错误直接中止整个流程并返回非零退出码：

- 编译扫描器失败。
- 运行扫描器失败。
- `all_keys.json` 未生成或内容不可解析。
- 数据库解密阶段整体失败。
- 联系人库或消息库目录不存在，无法进入导出阶段。

### 非阻断型错误

以下错误仅记录到最终摘要，不影响其他会话继续导出：

- 单个会话读取失败。
- 单个会话 JSON 写入失败。
- 某条消息字段异常导致归一化失败。
- 某个发送者昵称无法解析。

最终摘要应输出成功数、失败数及失败会话名，帮助用户定位问题。

## 兼容性与实现细节

- 保留现有 `export_chat.py` 的单会话导出能力，但其内部实现可以重构为“查询函数 + 单会话 CLI 包装层”。
- 新编排脚本默认只生成样例风格 JSON，不再生成 TXT/CSV。
- 一键流程中的 `sudo` 交互由终端本身处理；脚本负责在失败时提示“确认微信正在运行并已完成重签”。
- `--skip-scan` 和 `--skip-decrypt` 仅作为排障选项，不改变默认行为。
- 若用户未提供 `--keep-decrypted`，默认允许复用仓库内 `decrypted/` 目录，不主动删除历史解密数据，以避免误删用户文件。

## 测试策略

测试分为三层：

1. 单元测试：
   - 文件名清洗。
   - 重名去重。
   - 消息类型映射。
   - JSON 结构构造。
2. 夹具集成测试：
   - 使用最小化 SQLite 夹具验证“遍历全部会话 -> 生成多个 JSON”。
   - 不依赖真实微信进程或真实 `sudo`。
3. 手工验证：
   - 在真实环境中执行主命令，验证完整链路可运行。
   - 检查群聊和单聊各至少一份输出文件，字段符合样例结构。

## 实施计划预告

实现阶段将优先做以下工作：

1. 抽取 `export_chat.py` 中可复用的联系人解析、会话遍历和消息归一化逻辑。
2. 新增样例风格 JSON 构造器和全会话导出入口。
3. 新增一键编排脚本，将扫描、解密和导出串联起来。
4. 更新 README，补充新的“一键导出全部会话”用法。
